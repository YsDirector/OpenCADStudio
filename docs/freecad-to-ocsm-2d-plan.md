# FreeCAD → OCS/OCSM 二维工程视图：调研与实施计划

- 日期：2026-10-23
- 状态：**已完成首轮文档/源码核查与需求确认；尚未进行模型导出实测，尚未开发功能。**
- 目标：在 FreeCAD 中选择模型或既有 TechDraw 视图，导出可编辑、具有 OCSM 工程图层语义的二维 CAD，供 OCS 打开或插入。
- 首期入口：**FreeCAD 侧选择与导出，OCS 侧使用 DXF**；不以跨软件实时连接为前提。

## 1. 已确认的需求

### 1.1 三种输出模式

| 模式 | 内容 | 默认落层 |
| --- | --- | --- |
| 纯实线视图 | 全部可见工程边线，包括外轮廓、孔口、台阶等；不输出隐藏边 | 1；存在明确细线/中心线时分别为 2/3 |
| 实线＋虚线视图 | 可见工程边线＋被遮挡的不可见轮廓 | 1＋4；其他语义按需落层 |
| 剖视图 | 剖切后的可见轮廓、截面边界及截面填充；隐藏边单独设置，建议默认关闭 | 轮廓/截面边界为 1；填充为 5；需要隐藏边时为 4 |

这里的“纯轮廓”**不是仅最外圈剪影**，也不是删除孔口、台阶等内部可见边。

### 1.2 视向与投影

- 工程正投影：前、后、左、右、上、下。
- ISO 等轴测：正交轴测，不是近大远小的真实透视。
- 任意视向：规划支持当前相机方向/自定义方向；必须同时记录上方向或视图旋转，避免只存法向导致图形转向。
- 选择既有 TechDraw 视图时，规划继承其方向、旋转、隐藏线和剖切设置，但导出模型几何时去除纸面缩放。
- 相切边、曲面接缝分别设置开关；默认不把曲面接缝当作工程轮廓输出。
- 首先验证单视图导出；随后验证同一模型的多方向批量导出。组合排版如需支持，应显式处理第一角/第三角投影法。

**明确排除首期：**真实透视、自动尺寸标注、图框/BOM、双向关联更新、复杂阶梯/旋转/局部/半剖，以及完整国标简化画法自动推断。平面全剖是首期剖视基线，复杂剖视另行扩展。

## 2. OCSM 1—5 层映射

以当前 OCSM 源码 `crates/ocs_ocsm/src/lib.rs::layer_defs()` 为准，而非通用制图教材中的示例线宽。

| 图层准确名称 | 线型 | 线宽 | 输出语义 |
| --- | --- | --- | --- |
| `1轮廓实线层` | Continuous | 0.35 mm | 可见轮廓、孔口、台阶、剖切后的可见边界 |
| `2细线层` | Continuous | 0.18 mm | 明确标记的细实线、辅助/修饰线等；不按“短线”或“曲线”猜测 |
| `3中心线层` | CENTER2 | 0.18 mm | 已有或明确生成的轴线、对称中心线、圆心标记 |
| `4虚线层` | DASHED2 | 0.18 mm | 隐藏轮廓；保留连续几何边，以线型表达虚线，不切成大量小线段 |
| `5剖面线层` | Continuous | 0.18 mm | 剖面填充，优先原生 HATCH |

规则：

1. **剖视轮廓在 1 层，剖面填充在 5 层**；不是把同一轮廓复制到两层。
2. 颜色、线型、线宽均为 **ByLayer**；块内实体也必须正确，不能只设置 INSERT 的属性。
3. 不是每个视图都必须在 1—5 每层产生实体。中心线不是普通 BRep 边，不能假定投影算法会自动生成。
4. 相切边是否输出、输出后采用何种工程表达，应单独定义；不能机械地把全部平滑边归入细线层。
5. 图层、线型表和中文名称随 DXF 完整交付；导入已有 OCS 图纸时报告同名图层样式冲突，不静默覆盖。

## 3. 已核查的支持情况与证据边界

### 3.1 版本基线

- 本机安装包：`freecad 1.1.3-2`。
- 核查时 GitHub 官方 `releases/latest` 返回：稳定版 **1.1.4**，发布于 **2026-09-28**。
- 已对照 1.1.3 与 1.1.4 的 `src/Mod/TechDraw/App/AppTechDrawPy.cpp`；本任务关注的 DXF 导出主体相同。1.1.4 新增了 `scrubEdges` Python 入口，可列为去重候选，不能假定本机 1.1.3 具有该入口。
- 未升级本机软件，未启动 FreeCAD/OCS，未修改用户模型或图纸。当前未检测到 FreeCAD MCP 9876 端口监听，也没有可用的 OCS 会话；这不影响本轮静态规划。

### 3.2 已有能力

| 能力 | 文档/源码确认 | 尚需实测的部分 |
| --- | --- | --- |
| 正投影、ISO、任意方向 | TechDraw 的 Direction/XDirection/Rotation；Perspective 可关闭 | 坐标朝向、ISO 基向量、既有视图的缩放与旋转 |
| 可见/隐藏边区分 | `DrawViewPart.getVisibleEdges(True)`、`getHiddenEdges(True)`；`TechDraw.projectEx()` 分类结果 | 不同几何类型、过滤开关、装配相互遮挡、退化边 |
| 平面剖视 | `TechDraw::DrawViewSection`，具有剖切原点/法向、剖切面显示和填充设置 | 截面闭合环/孔洞提取、剖切保留侧、填充导出 |
| 二维 DXF | `TechDraw.writeDXFView`、`writeDXFPage` | 是否保留本任务需要的语义、实体类型、实际尺寸和中文图层 |
| Draft Shape2DView | 使用 `TechDraw.projectEx()`，可开关隐藏边 | 标准路径会将多类边合并为 Shape，不宜把最终混合结果当作可恢复完整语义的交付 |

### 3.3 关键限制

**不能将原生“导出 DXF”直接视为本任务完成。**

- 官方 `AppTechDrawPy.cpp::writeDXFView/writeDXFPage` 按视图名设置图层；`write1ViewDxf` 将可见硬边、轮廓、可选平滑/接缝边、隐藏边以及修饰线写入同一 writer 图层。该路径没有按 OCSM 1—5 层分类。
- 该 DXF 导出路径未见剖切面填充/HATCH 的专门写出；“页面能看到剖面线”不等于 DXF 中具有可用剖面填充。必须设为独立验证门槛。
- 官方文档注明页面 DXF 输出为 mm、按 TechDraw 页面尺寸导出，并有缩放及元素支持限制。不能未经测量便认为页面导出等于模型空间 1:1。
- `getVisibleEdges/getHiddenEdges` 默认返回 Qt 的 Y 向下坐标；本机对应版本支持传 `True` 获取常规坐标。仍须验证旋转、比例、位移，防止重复翻转/重复缩放。
- `projectEx()` 返回可见/隐藏的硬边、平滑边、接缝、轮廓、等参线等组。**等参线的 Iso 参数不是 ISO 等轴测开关。**
- 截面面域在 C++ 内存在，但不能把 C++ 的 `getCutShape/getSectionTopoDSFace` 等接口自动当成 Python 可调用方法；Python 侧截面拓扑的可获取性是技术探针重点。

## 4. 建议技术路线

```text
FreeCAD 选择对象 / 选择既有 TechDraw 视图
    ↓ 采集范围、Placement、视向、上方向、剖切参数
TechDraw / OCCT 精确 HLR 与平面剖切
    ↓
语义中间表示：二维曲线 + 可见性/工程角色 + 截面外环/内孔 + 来源
    ↓
DXF 输出适配器：OCSM 图层、ByLayer、单位、线型、HATCH
    ↓
OCS 打开 / 通用导入为块
    ↓
几何与图层回读 → 保存重开 → 视觉核对
```

### 4.1 原则

- **优先复用 FreeCAD 的几何与 HLR 能力，不重写投影内核，不走截图描图。**
- 原生导出作为对照基线，不以导出后按颜色猜线条类型为主方案。
- 候选实现：FreeCAD Python 宏/轻量面板＋语义适配器＋ezdxf。先验证 API 和数据链，再决定封装为工作台；不提前修改 OCSM Rust 核心。
- 依赖封装必须验证 FreeCAD 内嵌 Python 与系统 Python 的差异；可选择同进程打包或中间表示交给独立写出进程，不假设系统安装的库天然可被 FreeCAD 导入。
- 多体/装配在共同坐标系内**整体参与遮挡计算**，不能分别投影后简单叠加。剖面又需尽可能保留零件身份；不能默认 Fuse 后丢失接触边界。
- 优先保留 LINE/ARC/CIRCLE/ELLIPSE/SPLINE 等可编辑实体。只有显式允许时按记录的误差容限离散，不静默把全部曲线折线化。
- 截面填充优先原生 HATCH，保留内孔/岛。若仅能导出填充线段，必须在报告中标记为降级，并经过明确选择，不能伪称保留了 HATCH 语义。

### 4.2 路线比较

| 路线 | 作用 | 初步判断 |
| --- | --- | --- |
| TechDraw 原生 DXF＋后处理 | 建立基线，测试曲线写出质量 | 单独使用不足；若后处理需要源侧分类清单，实质仍需语义适配 |
| TechDraw 视图 API＋自定义 DXF 写出 | 复用既有视向/剖视，控制输出语义 | **首选验证路线** |
| `projectEx`＋Part 剖切/截面拓扑＋自定义写出 | 获取细粒度分类，补充 Python 截面 API 缺口 | 备选/补充；需验证与 TechDraw 页面结果一致 |
| Draft Shape2DView＋普通导出 | 快速生成可见投影，作为对照 | 不作为完整三模式的默认方案 |
| OCS FLATSHOT/SECTION 或屏幕隐藏线 | 对照宿主能力 | 当前实现不足以替代精确 HLR、隐藏线分层与完整剖视输出 |

## 5. 分阶段任务与决策门槛

### P0：冻结环境与原生能力基线

- 记录 FreeCAD/OCCT/Python、OCS/OCSM 版本及导出设置。
- 用可控测试副本建立样件；不对用户当前文档直接做实验。
- 对比 TechDraw 原生单视图/页面 DXF、ProjectShape、Draft Shape2DView。
- 记录实体类型、图层、单位、已知尺寸、隐藏线、剖面填充及耗时。
- 先固定一个可复现版本运行；1.1.3 为本机基线，1.1.4 用于差异核验，升级需另行决定。
- **产出：**支持矩阵、原生导出缺陷清单、样例 DXF 与截图。

### P1：可见/隐藏边与坐标技术探针

- 实测视图 API 与 `projectEx` 的可见性和类别，覆盖孔口、盲孔、圆柱轮廓、相切边、接缝。
- 检查全部六个正投影、ISO 和至少一个任意方向；验证 Direction＋上方向＋旋转。
- 检查既有视图 1:2、2:1 比例及旋转，输出仍不带纸面缩放。
- 验证 Body Tip、容器 Placement、App::Link/装配位置与选定范围；不能遍历导出整份文档的历史/隐藏特征。
- **门槛：**可靠得到可见边与隐藏边、常规 XY 坐标和来源信息；否则先报告 API 缺口，不进入完整 UI 开发。

### P2：剖切拓扑与填充技术探针

- 先验证一个平面全剖，明确剖切原点、法向、保留侧与输出视向。
- 验证截面外环、内孔、多个不连通面域及零件分组。
- 核对 TechDraw 截面拓扑是否可经 Python 获取；必要时用同一源 BRep 和剖切平面重建面域，并验证坐标对齐。
- 在 OCS 验证原生 HATCH 的边界、孔洞、角度、间距及保存重开表现；SVG 纹理不是合格替代品。
- **门槛：**轮廓正确落 1 层、填充正确落 5 层，孔内不填充、非剖切区域不误填。若只能降级，列清损失再决定是否接受。

### P3：统一 DXF 输出与 OCS 兼容

- 实现语义映射、ByLayer、线型/图层表、mm 单位、去重与退化边检查。
- 以支持 Unicode 的现代 DXF 为候选（如 DXF 2013），经 OCS 读写验证后固定版本；不要默认沿用原生 R12/R14 与旧编码链。
- 先交付单视图 DXF，再提供多方向批量输出；组合输出时以每视图一块或清晰分组管理，内部实体仍使用 1—5 层。
- 确保视图间只是布置平移，不能为排版改变几何尺度；留存视向、原点、比例、源对象、导出设置与误差容限。
- 验证“独立打开”和“导入已有 OCS 图纸”两条路径；检测同名图层/线型冲突，不静默重定义。
- **门槛：**OCS 读回、保存重开后，几何与工程语义均未丢失。

### P4：FreeCAD 交互封装与交付

- 输入范围：选中模型对象或已有 TechDraw 视图，不默认输出全部文档。
- 控件：视向/当前方向、上方向/旋转、三种模式、隐藏边开关、相切边/接缝、剖切平面、填充角度/间距、预览、目标路径、批量视图集合。
- 输出前报告范围、单位、模式与预计图层；空选、空结果、无效 BRep、未就绪投影、计算超时等给出明确错误。
- 等待 TechDraw 的异步 HLR/剖切完成后再写文件；不能在未完成时导出空白后返回成功。
- 保持用户模型不被破坏；临时对象在独立导出上下文或事务中管理。
- 文档、自动测试、示例及失败案例说明齐备后，才标记首期可用。

## 6. 验证矩阵

| 样件 | 重点 |
| --- | --- |
| 带台阶、通孔、盲孔的非对称块 | 六方向朝向、内部可见边、隐藏轮廓、盲孔深度表现 |
| 空心轴套/带阶梯孔零件 | 剖切轮廓、内孔/岛、壁厚、HATCH 不填孔 |
| 带圆角、圆柱接缝、曲面/样条的零件 | 相切边/接缝开关、ISO 椭圆、样条、重复边与曲线保真 |
| 两个相互遮挡或接触的实体 | 全局遮挡、接触边界、分零件截面与填充方向 |
| 一个经用户指定的真实零件副本 | 工程可用性、性能、人工对照及失败覆盖 |

基础组合：六个正投影＋一个 ISO，各测试纯实线/含隐藏线；剖视至少覆盖 X/Y/Z 基准平面、偏置平面、内孔和多面域。另加入一个任意视向、一个旋转/缩放既有视图、一次重复导出及保存重开回归。

性能只在记录样件规模（体/面/边数）后报告；暂不承诺大装配统一耗时指标。

## 7. 验收标准

1. **范围正确：**只处理选定模型/视图；历史特征、未选部件不混入输出。
2. **模式正确：**纯实线无隐藏边；含隐藏线模式中可见边不错误归虚线；剖视不是仅输出一条截交线，而是符合设定保留侧的完整几何表达。
3. **分层正确：**1—5 层语义、名称和 ByLayer 均可程序回读；不是仅凭截图颜色判断。
4. **几何正确：**正投影已知尺寸偏差暂定不超过 0.01 mm，最终按样件尺度/用途确认；ISO 按数学投影验证，不能要求二维投影边长等于三维原长。
5. **填充正确：**轮廓闭合、内孔不填、无实心误渲染；剖面线角度/间距可控，移动/保存后不丢失。
6. **实体可编辑：**优先保留解析曲线；若离散或填充降级，报告具体实体、误差与损失，不静默处理。
7. **兼容正确：**OCS 独立打开、通用导入、保存重开后结果一致；审计实体类型/数量/边界/图层，并完成至少关键样件的实际视图截图核对。
8. **失败可解释：**不支持的几何或 API 缺口不会得到“导出成功但实体缺失”的交付。
9. **可复现：**样件、设置、版本、统计报告和期望结果齐全；结构审计通过不代替工程语义核对。

## 8. 特别风险与非目标

- **几何剖切不等于自动符合全部机械制图规范。**螺栓/轴纵剖、肋板不剖、螺纹/齿轮简化表达等不能仅从普通 BRep 边线可靠推断；需要后续规则、零件元数据或人工控制。
- 中心线可保留已明确存在的语义；自动识别对称轴/孔阵列圆心应作为独立增强项，不作为通用 HLR 自带能力承诺。
- HATCH 的图案向量、角度、闭合环与间距必须按 OCS 实际读法验证，防止“数据存在但显示空白/实心”。
- 当前 OCS `-INSERT` 的外部文件回退逻辑可能给 DXF 名称追加 `.dwg`。导入验收应走经确认的通用文件导入入口，不能把该命令假定为已可用的 DXF 自动化通道。
- 当前 OCSM 没有现成的 FreeCAD/TechDraw 转换实现；宿主已有 FLATSHOT/SECTION/屏幕隐藏线也不等于可编辑、已分类的工程投影视图。
- 不以 MCP 已运行为最终使用前提。实际自动化验收若采用 FreeCAD MCP，服务器由用户手动启用；本轮不启动、不修改其配置。

- 投影复用 OCCT HLR（`projectEx`/`getVisibleEdges` 同级能力），全部选中实体共同参与遮挡；
  Body Tip、容器/链接 Placement、七视向 + 任意视向 + 旋转均已覆盖。
- 平面全剖用逐实体有限半空间裁切重建切面拓扑（外环/内孔/多区域），不依赖未经证实的 C++ 截面 Python 入口。
- 既有 TechDraw 普通视图/子视图/平面剖视的设置继承已实现；纸面比例被显式忽略并记录。
- 入口：FreeCAD 工作台 + 宏 + 独立 modeless 面板（纯 SVG 预览）、`install.py`（非破坏登记）、Python API。
- 证据：真实 FreeCAD 1.1.3 内核测试 35 项；样件 14 份 DXF；原生 DXF 对照确认单层/无 HATCH 缺口；
  OCS 2026.42 无界面 codec 往返 14/14 通过（详见 README 第 6 节及 `artifacts/`）。
- 后续交互测试补齐：第一角/第三角布局（不再横排）、每视图独立的纯实线/隐藏/全剖/全剖+隐藏、
  degree-1 非有理样条转 LINE 并合并相接共线线段。
