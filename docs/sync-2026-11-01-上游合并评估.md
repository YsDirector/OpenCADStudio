## 3. 结构性风险（比文本冲突更吃时间）

### R1 · codec 二次改名 + 新的 `Document` 包装类型（高风险）
- 上游：`codec = { package = "opencaddocument", git = ".../opencaddocument.git", rev = "d657f94" }`；
  `opencaddocument` 内部再依赖 `acadrust`（新仓 `HakanSeven12/acadrust`，rev `53e6420`）。
- 我们：`codec = { package = "acadrust", git = ".../opencadcodec.git", rev = "14fdae5" }`（单层）。
- **关键缓解（已核实源码）**：`opencaddocument::Document` 是 `acadrust::CadDocument` 的
  `#[serde(transparent)]` newtype，`Deref`/`DerefMut` 指向它，并双向 `From`：
  ```rust
  pub struct Document(acadrust::CadDocument);           // Deref/DerefMut -> CadDocument
  pub use acadrust;  pub use acadrust::*;               // CadDocument 仍在
  ```
  ⇒ **fork 侧 1693 处 `CadDocument` 不必全改**（其中 34 个文件/960 处在 `crates/ocs_ocsm`）。
  需要改的是**类型签名与构造点**：`HostApi::document() -> &Document`、`Document::new()`、
  `document_mut()`、以及上游 host 侧已统一成 `Document` 的调用点。
- 仍需重建的：`crates/ocs_plugin_api/build.rs` 在 `Cargo.lock` 里找的是 **`acadrust`** 包（上游已同步保持这个名字），
  我们的锁文件升到新 pin 后**必须重新生成 `Cargo.lock`**，否则 `expect("codec package (acadrust) in Cargo.lock")` 直接 panic。
- `plugin.toml` 的 `acadrust_source` **键名不变**，但**值必须重取**（部署脚本会替换；CI/门禁会拒错的）。
- 依赖升级带来的 `acadrust 0.6.x → 53e6420` 内部 API 差异：宿主能编过是因为上游改完了，
  **插件侧（`crates/ocs_ocsm`，180 文件）才是未知数** —— 这是本轮最大的未知工作量。

### R2 · Plugin API v13 → v14（中等，但改动面广）
- 插件的 `plugin.toml` 现在要 `api_version = 14`；`export_plugin!` 额外生成 `ocs_plugin_run`；
  服务器门禁从「rustc + codec commit 严格相等」变成「wire schema 指纹」。
- 对我们**是利好**：`.so` 与宿主的 rustc/codec 绑定解除，以后宿主升级不必同年重编插件。
- 代价：`crates/ocs_ocsm/src/lib.rs` 的 `MANIFEST`/`export_plugin!` 与 `plugin.toml` 要跟着改，
  且 v14 之后 `api_version_min_supported` 仍是 3（老插件不受影响）。

### R3 · undo 组撞车（低风险，高收益）
- fork：`HostApi::begin_undo` / `commit_undo` + `PendingHistorySnapshot.deferred`
- 上游：`begin_undo_group` / `end_undo_group` + `PendingHistorySnapshot.held`（`6fca8eaea`）
- 处置：**改用上游命名与实现**，fork 的 `deferred` 字段并入 `held`；
  `plugin_host.rs` 的 `begin_deferred_undo`/`commit_deferred_undo` 改名转发。
  收益：ledger §0.7 的一整类补丁退役。

### R4 · 面板/工作区扩张（低）
- 上游新增 `PanelId::Laywalk`、`QuickCalc`；fork 有 `Pi`。三方并集 = 14。
- 上游把调色板/停靠区重构（自动隐藏、浮动组、可拖标签），fork 对 `ui/dock.rs` 有宽度策略改动 ⇒ 合完要在真机上看一眼面板布局。

### R5 · 别名 `D`（需决策）
- 上游 `src/command.rs`：`"DIMSTYLE" | "D" => "DIMSTYLE"`；`"STYLE" | ... | "S" => "STYLE"`。
- fork `src/app/alias.rs`：把已存别名 `D = DIMSTYLE` 一次性改写成 `QDIM`（OCSM 的快速标注习惯）。
- 两者不冲突到编译，但**语义冲突**：合并后按 `D` 到底出 DIMSTYLE 还是 QDIM，是产品选择。

### R6 · 构建与磁盘（低，但要提前腾）
- 仓库在 btrfs loop 上：240G / 已用 209G / **剩 29G**。
- 旧 worktree 的 `target/` 可回收：`ocs-upstream-merge-v2026.41` 27G、`ocs-codec-bump` 3.1G、`pr-trim-hatch` 3.1G。
